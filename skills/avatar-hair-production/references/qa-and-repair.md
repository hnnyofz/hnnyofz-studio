# 质量判断与常见修复

先找最早出错的环节，不把所有问题都变成改PNG或改运行时偏移。小修先验证问题格与邻居，批量前用一款代表样本；变更验证通过后不重复无关的大审计。

| 现象 | 区分证据 | 修复方向 |
|---|---|---|
| 整副悬空、额头过高 | 三维发根到代理头距离；站立/转头/说话共同偏差 | Blender整体平移/局部贴合，核对变换只应用一次；别只压发际线 |
| 顶部“超级大头” | 与批准头部在相同64px视口下比顶部高度 | 调真实尺寸；宽双髻/双马尾不等于顶部比例错误 |
| 抬头看侧上角出现裸肤竖条 | 同角度front/rear、真实head、完整parts与hair-only | 判断近侧实体缺覆盖，还是已可见后发被2D head遮住；分别补3D根部/修语义层 |
| hair-only看似有发，但真实皮肤仍漏 | 这些射线可能命中远侧或封口内壁，完整pass是head1 | 补真实近侧表面，不把远侧内壁涂到脸上；禁耳也未必解决，因为其后仍有头体 |
| 张嘴时嘴角漏底 | 完整proxy头较真实2D说话头宽，且hair-only有真实发色 | 仅恢复真实head/face透明区的误裁发色，同姿态采样；不要覆盖嘴和皮肤 |
| 背面整体黑、层次少 | 转模型与绕到背后拍摄是否保持同一光照；纹理是否烘死暗部 | 固定世界光、材质家族内法线补偿、保留高光/中间色/暗部 |
| 背面正中硬分割 | 纹理烘焙和左右材质边界 | 偏心宽光、连续体积/法线与发束细节，不整面涂亮 |
| PNG或网页有单像素凸点 | 原生1:1、8连通、颜色/语义、是否细结构末端 | 逐点修轮廓：移除外黑点时补好内边描边；保留尖刺和发饰细带 |
| 缩略图歪、和灰头不合 | 取帧是否为row4/col6及固定偏移 | 用批准icon姿态与灰头，不取纯正面或逐款重新居中 |
| 改过发色却仍旧色 | Blender packed image和磁盘PNG是否相同 | reload后重新pack，重建viewer并核对source/runtime/texture哈希 |

## 已知角度的回归

第1行第9列（零基0/8）曾暴露侧根缺失；同时看0/7、1/8、1/7、中立4/4和反方向0/0。典型修复是在真实scalp/ear表面外新增两侧局部闭合cap，上端接入原发根，下端保留耳垂/面颊；新增表层归front语义2，原hair/head/UV尽量保留。

曾用过的cap域 `YZ中心[1,25.6]、半径[4.4,5.1]` 只属于本项目代理头。它是案例，不是对所有头模的通用坐标。目标头不同，就在其真实表面采样、对照耳线和面颊，再限定局部范围。不要复制固定的世界坐标盲盖所有发型。

## 验收的实际尺度

- 主视图：整体轮廓、分缝、头顶高度、侧根与后颈连接、配色身份。
- 动态姿态：左右、抬头两角、低头、背面；说话5相位及必要翻转。不为全绿擅自抬发型，发梢触画布边界可记录审阅，明显截断才改构图/几何。
- 合成：使用真实头像素材与实际Avatar runtime。纯hair-only预览、代理白模和人工静态拼图不能替代实际接入。
- 原生像素：保留整数像素和全透明背景；先看1:1，再整数nearest放大。不要把抗锯齿截图当成正式PNG。
- 图集：136唯一格、尺寸与RGBA8正确、目录/catalog一致，source→renderer→GPU→PNG→安装哈希可追溯。

## 汇报与交接

外观名而非角色名；每款共用视口、锚点和放大倍数，正背两张放一起。GIF用真实已导出的姿态循环，不能光学流补帧假装新角度；需要时使用一个共享精确palette并验证解码RGB与原帧一致。

交付清单包括：需求、三视图与裁图manifest、原GLB与生成状态、完整及分区Blender场景、realtime/spec、冻结sourceSHA、像素图集与图标、修复/来源manifest、安装备份、预览网页地址/启动方法。用户未要求发布则本地交付即可；有MR范围时附具体改动与实际检查结果。

模型或关键源步骤没执行就写明“未生成/未验证”，不因schema可读取就声称免费生成成功，也不因文件存在就跳过模型与浏览器验证。
