# 发型描述与三视图

## 用可制作的外观描述代替角色名字

角色／影视参考可以作为设计依据，但给团队的名称和交付列表使用发型外观名，例如“银灰侧扫短发”“绑带双髻”“金色中分短发”。需求至少包含：

| 项目 | 需要明确的内容 |
|---|---|
| 外轮廓 | 短／中长／长、宽度来源、头顶高度、后颈收口 |
| 前区 | 分缝比例、刘海走向、额头覆盖、左右是否有意不对称 |
| 侧区 | 太阳穴到鬓角的连接、耳朵露出程度、发根贴合 |
| 后区 | 体积、层次、发束走势、辫子／马尾实际连接位置 |
| 配色 | 主发色及亮／中／暗 ramp，发饰独立色系 |
| 风格 | 同一中性 Q 版头模、玩偶式圆润体积、能读成像素轮廓 |

采用 [hair-brief.example.json](../assets/hair-brief.example.json) 的粒度即可，不必为每个项目建复杂规格。批量时先列候选、去除仅换角色但轮廓相同的重复项；按任务挑选数量，保留待选与已批准的状态。

## 一致三视图提示词骨架

> 为一个可拆卸 Q 版玩偶发型绘制正交头部三视图：左为纯正面，中为真实右侧面，右为背面。三图是同一个发型、同一个中性小人头、同一比例和高度；白色背景，完整保留发梢。发型为【轮廓/刘海/侧根/后发/发饰】，颜色为【色板与分区】。发根贴头，头顶比例按【参考头】；浅而稳定的体积光，不用强阴影遮挡结构。只含头部，不含肩膀、身体、道具；图内不放文字、水印、分隔线。

这不是固定美术风格模板：用户有指定造型、配色或线条时沿用它。对非对称分缝明确哪个侧面是真的 right；不把正面镜像充当侧面，也不为了对称抹掉有意设计。

## 冻结与裁图

先肉眼确认三图的双髻／马尾数目、后发长度、分缝位置、头顶比例和发饰连接一致。明显矛盾先改三视图，别把不一致输入交给生成模型后再猜。

裁图只做矩形裁切与共同画布补边。保护最长发梢、排除文字。三个方向使用同一像素尺度；不要独立裁紧后各自缩放到同尺寸，那会改变前后发量。不同原图尺寸先明确共同头高标尺，记录任何必要的统一缩放。

`boxes.json` 示例（对一张960×320的三联图）：

```json
{"front":[0,0,320,320],"right":[320,0,640,320],"back":[640,0,960,320]}
```

```sh
python "$SKILL/scripts/prepare_views.py" \
  --sheet references/three-views.png --boxes boxes.json --out inputs
```

输出共同画布与 input-manifest，记录原图 SHA、裁切矩形和各图 SHA。透明图会铺白；820／768 方图是可选工作分辨率，不是免费 API 必须遵守的硬编码尺寸。
