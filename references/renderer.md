# Shared preview and shader

The starter is self-contained. It does not depend on the presence of the original Colorfigures or pixel-sprite skill. `provenance.json` identifies the local sources and content hashes used to create it.

## Render contract

`model.json` contains `settings`, `materials`, `textures`, `chunks`, `parts`, `cameras`, `bounds` and source/geometry hashes. Each chunk has a `structure` ID, `material` index, `moving` flag and interleaved triangle vertices: XYZ, normal XYZ, UV (8 floats). All chunks render with depth testing; geometry is never sorted with SVG painter ordering. Materials use RGB values and optional packed RGBA textures; the procedural starter supplies flat colors.

Cameras provide a column-major `viewProjection` mat4, `viewNormal` mat3, `orthographicSize`, `depthRange` and name. One `state.angle`, `state.zoom` and selected camera drive both viewport halves. The raw view displays the beauty texture generated by the same geometry pass whose depth and normals feed the pixel pass. A shared canvas with two viewports guarantees frame synchronization; two independent animation loops are unnecessary.

## Passes

1. `meshVert`/`meshFrag`: render geometry at eight times native width/height into beauty, packed 16-bit depth and component/normal attachments.
2. `sampleFrag`: count occupancy per 8×8 block; discard less-than-half covered cells; choose the dominant visible component. Color, depth and normal are sampled only from that component. Optional palette voting maps colors to the declared palette.
3. `finishFrag`: add a one-native-pixel silhouette stroke only to transparent cells with an occupied four-neighbor. Existing material cells retain their color. All decisions sample the original buffers, preventing recursive expansion. Optional contact ink extends the front part's border onto the rear part; depth extrapolation to the shared edge determines a single owner. Require two further same-component cells inward on the recipient side to protect narrow posts and slats. Existing ink on either surface consumes that boundary's ink budget. Bright upward-facing surfaces may use `deepOutline`; set it equal to `outline` for uniform ink.
4. `displayFrag`: show the raw beauty on the left and native pixel result on the right. Pixel enlargement is nearest-neighbor and integer-scaled in device pixels. Both halves share framing and zoom.

The shared pipeline comes from the local pixel demo and its generic skill runtime. The demo's role-based office-chair paint rules, caster logic, hardcoded native canvas and fixed floor footprint are excluded. A separate mask pass flattens the actual rotated triangles onto the ground at the model's minimum Z, representing vertical parallel sunlight. It uses the same view projection and zoom as both views. Overlapping triangles write one mask without blending, so shadows do not accumulate darkness. The raw view composites the mask behind beauty; the pixel view applies a 50% occupancy threshold per 8×8 block and composites a 26%-opacity tint after ink. This shadow does not enter semantic IDs, palette voting or silhouette/contact detection, and remains semitransparent in PNG exports. This is a ground projection, not a self-shadowing lighting system. The page uses subtle CSS paper grain; it is not baked into GPU beauty or exported PNGs. SVG line wobble is not part of this renderer.

## Controls and exports

All display controls reference one state. Yaw uses eight buttons (0°, 45°, …, 315°) and free dragging; only an exact preset angle receives `aria-pressed=true`. The row scrolls horizontally on narrow screens. Playback, speed, reverse, numeric yaw and the yaw slider are omitted. Density changes rebuild GPU targets; they do not substitute another model. Zoom changes the same projection for both sides and scales `worldPixel` used for contact ownership. Camera changes retain yaw. The current angle, camera, zoom and draw counter are exposed as DOM `data-*` attributes on the canvas for read-only acceptance.

PNG exports read actual GPU pixels, flip their row order and preserve transparency. Rotation ZIPs contain angles in `[0,360)` with no duplicate 360° frame, current settings and source/geometry hashes. They restore the starting angle and selected preset after rendering. Export style changes require fresh captures.

On unsupported WebGL2, show the actual error; do not silently replace the model with a screenshot and call it a live shader. Shader edits require overlapping-same-color contact tests and inspection at multiple cameras. Do not claim pixel-perfect reference reconstruction unless separately verified.

## Repeatable shader fixture

Run `node build.mjs contact-fixture.mjs runs/contacts` in a newly scaffolded project. The bundled fixture uses three overlapping rounded green blocks, a 48px canvas, and oblique/top cameras. Compare contact ink enabled/disabled; only visible boundaries should appear. It deliberately uses another palette and silhouette than the chair.

## Outer-stroke regression

Capture the diagnostic raw, result and edge buffers over a rotation sweep. With contacts disabled, assert all occupied raw RGBA cells are unchanged; new opaque pixels and the red edge mask must exactly match a one-cell four-neighbor dilation minus the raw occupancy. With contacts enabled, red remains exterior-only and green marks eligible rear-surface contact cells. Check side-on thin parts at the chosen native resolution and confirm 0° and 360° match. Outer strokes increase silhouette extent by one native pixel; keep framing margin.

Verify ground shadows in oblique and side views, across rotation and zoom, and from directly above (the model should cover its own vertical projection). Compare pre/post shadow model and ink pixels; only previously transparent pixels may receive semitransparent shadow. Diagnostic `ground-shadow` exposes the projected mask.

## Finish presets

Author `scene.finishes` as `[{id, name, swatches:[hex,hex], colors:{[sourceHex]:targetHex}}]`. Source hex keys must exist in the scene palette or material table; values must be valid RGB hex. `scene.finishName` and `scene.finishSwatches` label the untouched original, which build.mjs always inserts first. The bundled `furnitureFinishes(primary, accent)` maps matching light/mid/dark/under ramps to six coordinated alternatives. Source colors reused by several parts change together; use separate source colors or explicit maps when that is not intended. The flat-color starter does not remap embedded texture texels.

The builder expands each finish into material-index RGBs, a palette of the same length as the original and ink/deep colors. Geometry indices and IDs are unchanged. Runtime switches the material uniform, palette array uniform and ink uniforms together without recompiling shaders or replacing geometry. PNG exports use the live finish; ZIP manifests include finish ID/name/palette. Switching finish hides stale current-image and ZIP downloads. `canvas.dataset.finish` exposes the current ID for QA.

Pixel density is the first always-visible control below the preview; it must not be hidden in the advanced disclosure.

The shell follows Colorfigures' warm paper, monospace type, fine rules, capsule buttons and circular swatches. The presentation canvas uses paper instead of a checkerboard; the exported-image preview retains a transparency checker. Grain is display-only. Keep the 45° yaw row and dual views; do not reintroduce cutaway or mechanism controls as part of this visual styling.
